**`build_loaders(dataset, batch_size, val_ratio, seed, snr_min)` function:**
Follow `synth_finetune.py:make_loaders` pattern:
1. Create a logger: `logger = logging.getLogger('at_loader'); logger.setLevel(logging.WARNING)`
2. Call `Load_Dataset(dataset, logger, snr_min=snr_min)` — returns (Signals, Labels, SNRs, snrs, mods)
3. Use `np.random.default_rng(seed).permutation(len(Labels))` for 85/15 split (per D-10)
4. Create `TensorDataset` from Signals and Labels tensors directly (they are already torch tensors from Load_Dataset)
5. Return `(train_loader, val_loader, Signals, Labels, SNRs)` — the raw arrays are needed later for validation FGSM eval
6. Print dataset size: `f"  AT dataset: {n_train} train, {n_val} val (SNR >= {snr_min} dB)"`

**`make_attacks(wrapped_model, eps, pgd_steps, ead_iters, ead_bss)` function:**
Per D-04, D-02, D-03. Instantiate all 4 attack objects and return a dict:
```python
import torchattacks
attacks = {
    'fgsm':  torchattacks.FGSM(wrapped_model, eps=eps),
    'pgd':   torchattacks.PGD(wrapped_model, eps=eps, alpha=eps/4, steps=pgd_steps),
    'eadl1': torchattacks.EADL1(wrapped_model, kappa=0, lr=0.01,
                                  max_iterations=ead_iters, binary_search_steps=ead_bss),
    'eaden': torchattacks.EADEN(wrapped_model, kappa=0, lr=0.01,
                                  max_iterations=ead_iters, binary_search_steps=ead_bss),
}
return attacks
```

**`generate_adv_batch(wrapped_model, x, y, attack)` function:**
Per D-05, D-08.
1. Import `iq_to_ta_input_minmax`, `ta_output_to_iq_minmax` from `util.adv_attack`
2. `x01_4d, a, b = iq_to_ta_input_minmax(x)`
3. `wrapped_model.set_minmax(a, b)`
4. `with torch.enable_grad(): adv01_4d = attack(x01_4d, y)`
5. `wrapped_model.clear_minmax()`
6. `x_adv = ta_output_to_iq_minmax(adv01_4d, a, b)`
7. Build analog mask: `analog_mask = torch.tensor([yi.item() in ANALOG_INDICES for yi in y], dtype=torch.bool, device=x.device)`
8. If `analog_mask.any()`: `x_adv[analog_mask] = x[analog_mask]`
9. Return `x_adv.detach()`

**`train_epoch(model, wrapped_model, train_loader, attacks, optimizer, criterion, alpha, device)` function:**
Per D-04, D-06.
1. `model.train()`
2. Initialize accumulators: `total_loss = 0.0`, `total_loss_clean = 0.0`, `total_loss_adv = 0.0`, `n_samples = 0`
3. For each `(sig, lab)` batch from `train_loader`:
   a. Move to device
   b. Select attack: `attack_name = random.choice(ATTACK_NAMES)` then `attack = attacks[attack_name]`
   c. Generate adversarial batch: `x_adv = generate_adv_batch(wrapped_model, sig, lab, attack)`
   d. Clean forward: `logit_clean, regu_clean = model(sig)`
   e. Adversarial forward: `logit_adv, regu_adv = model(x_adv)`
   f. Compute loss per D-06: `loss_clean = criterion(logit_clean, lab)`, `loss_adv = criterion(logit_adv, lab)`, `loss = alpha * loss_adv + (1.0 - alpha) * loss_clean + sum(regu_adv)`
   g. `optimizer.zero_grad(); loss.backward(); optimizer.step()`
   h. Accumulate: `total_loss += loss.item() * len(lab)`, `total_loss_clean += loss_clean.item() * len(lab)`, `total_loss_adv += loss_adv.item() * len(lab)`, `n_samples += len(lab)`
4. Return `(total_loss / n_samples, total_loss_clean / n_samples, total_loss_adv / n_samples)`

Note on D-06 regu_sum: Add `sum(regu_adv)` only (from the adversarial forward pass), not both. This follows the RESEARCH.md interpretation of "added once per forward (detail)".

**`val_epoch(model, wrapped_model, val_loader, attacks, criterion, device)` function:**
Compute both clean accuracy and FGSM robust accuracy on the validation set (per D-12).
1. `model.eval()`
2. Clean accuracy: iterate val_loader with `torch.no_grad()`, compute `logit, _ = model(sig)`, count correct predictions.
3. FGSM robust accuracy: iterate val_loader, for each batch call `generate_adv_batch(wrapped_model, sig, lab, attacks['fgsm'])` (always FGSM for val, per D-12), then `with torch.no_grad(): logit, _ = model(x_adv)`, count correct.
4. Return `(val_clean_acc, val_robust_fgsm_acc)`

Note: The model must be in `.eval()` mode for clean inference but attack generation needs gradients. The `generate_adv_batch` function uses `torch.enable_grad()` internally, so this is handled. However, the model should be set back to `.train()` temporarily for attack generation to ensure BatchNorm behaves correctly for gradient computation. Implementation: before calling `generate_adv_batch` in val_epoch, call `model.train()`, then after generating x_adv, call `model.eval()` for the inference pass.
