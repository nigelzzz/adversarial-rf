    **Subsection A — AWN Classifier Architecture:**
    - Input: IQ signal tensor [batch, 2, 128] from RML2016.10a
    - Feature extraction: 2D conv integrates I/Q channels, 1D conv for temporal features
    - Adaptive wavelet decomposition: learnable lifting scheme (Predictor P, Updator U)

    **Subsection B — Attack Models:**
    - Formally define 4 attack types used in evaluation:
      - FGSM: single-step gradient, `x_adv = x + eps * sign(grad_x L)` — cite goodfellow2015fgsm
      - PGD: iterative projected gradient descent with random start — cite madry2018pgd
      - CW (Carlini-Wagner L2): optimization-based, minimizes `||delta||_2 + c * f(x+delta)` — cite carlini2017towards
      - EAD (Elastic-net): L1 + L2 penalty, `beta * ||delta||_1 + ||delta||_2 + c * f(x+delta)` — cite chen2020ead
    - Note: all attacks use minmax normalization for IQ signals (map per-sample to [0,1] for torchattacks)
    - Equation block for each attack objective

    **Subsection C — Threat Model:**
    - Attacker: white-box access to classifier, defense-unaware (does not adapt to our defense)
    - Attacker goal: misclassification (untargeted)
    - Attacker constraint: perturbation bounded by epsilon (Linf for FGSM/PGD, L2 for CW, elastic-net for EAD)
    - Defender: can preprocess input signal before classification, no access to attack parameters
    - Deployment assumption: real-time constraint (defense must not introduce prohibitive latency)

    **Subsection D — Deployment Contexts (brief, 1 paragraph):**
    - Mention 3 contexts from adaptive_k_report.md: ITU/FCC spectrum monitoring, CBRS SAS, military ESM

    **2. Write `proposed_method.tex`** (~2 pages, ~150-200 lines):

    This is the main technical contribution section. Adapt from USENIX Sections 3-4 and expand with classical baselines.

    **Subsection A — Control-Plane Attack Insight (motivation, ~0.5 page):**
    - Condense USENIX Section 3 into a motivational paragraph + one small table
    - Key finding: CRC checks pass on adversarially perturbed signals when demodulated with oracle → attacks target classification (control plane), not data integrity
    - This motivates frequency-domain defense: if perturbations are in the spectral domain, filtering can remove them without destroying the underlying signal
    - Brief table (or inline numbers): CRC pass rate before/after oracle demod for a few attacks

    **Subsection B — FFT Top-K Filtering:**
    - Define the base operation: compute rFFT, keep K largest magnitude bins, zero others, apply iRFFT
    - Equation: `x_filtered = iRFFT(TopK(rFFT(x), K))`
    - Normalization: signals normalized to [0, 1] before FFT, denormalized after
    - This is the building block for both adaptive-K and spectral-gated methods

    **Subsection C — Spectral-Gated Defense (Algorithm 1):**
    - Compute spectral flatness: `SF = exp(mean(log(|X|))) / mean(|X|)` (geometric mean / arithmetic mean of magnitude spectrum)
    - If SF > threshold: bypass Top-K (signal is wideband, like AM-SSB, where Top-K would destroy it)
    - If SF <= threshold: apply Top-K with fixed K
    - Present as `\begin{algorithm}...\end{algorithm}` environment with `\caption{Spectral-Gated Defense}`
    - Adapt directly from USENIX Section 4.3 Algorithm

    **Subsection D — Adaptive-K Defense (Algorithm 2):**
    - Per-sample K selection based on spectral magnitude knee-point
    - Sort FFT magnitudes descending, find elbow/knee where cumulative energy exceeds threshold
    - K = index of knee point (adapts to signal bandwidth)
    - Present as Algorithm 2
    - Explain why adaptive is better: narrowband signals (BPSK) need small K, wideband (AM-SSB) need large K

    **Subsection E — Classical Filter Baselines:**
    - Brief description (2-3 sentences each) of the 5 classical filters used as baselines:
      - **Kalman filter:** state-space model treating IQ samples as noisy observations; optimal for linear Gaussian noise
      - **Wiener filter:** MMSE estimator in frequency domain; assumes stationary signal + noise
      - **Savitzky-Golay filter:** polynomial smoothing via local least-squares fit; preserves signal shape
      - **Gaussian filter:** convolution with Gaussian kernel; low-pass smoothing
      - **FIR filter:** finite impulse response low-pass filter with configurable cutoff
    - One sentence on why they are relevant baselines: "These represent the standard signal processing toolkit a communications engineer would apply before considering ML-based defenses."
    - Note: all filters are calibrated per-SNR using grid search on validation accuracy (cite Phase 2 calibration)
    - Also mention **randomized smoothing** as a certified defense baseline

    **Subsection F — Complexity Analysis:**
    - Brief analysis of computational complexity:
      - FFT Top-K: O(N log N) for FFT + O(N log K) for top-K selection
      - Classical filters: O(N) for FIR/Gaussian (convolution), O(N^2) for Kalman (per-sample state update)
      - Note: Gaussian and FIR are GPU-native (implemented as depthwise conv1d); Kalman and Wiener require CPU fallback
    - Keep to one paragraph — detailed latency numbers go in Results section
