<objective>
Implement the minimal `--ckpt_path` shim (D-01 option a) so that `main.py` accepts
either a directory (existing behavior: joins with `<dataset>_<MODEL>.pkl`) OR a
full path to a `.pkl` file (new behavior: uses the path verbatim). This unblocks
Phase 5 which must load `./checkpoint/2016.10a_AWN_at.pkl` through the existing
`--mode defense_compare` dispatch without copying the AT checkpoint to the
canonical filename or editing `get_ckpt_name()` return.

Purpose: Without this shim, every eval mode in `main.py` would try to load
`./checkpoint/2016.10a_AWN_at.pkl/2016.10a_AWN.pkl` (directory-join bug) and
fail. The AT checkpoint must be loadable through the standard `--ckpt_path`
interface without special-casing the AT filename.

Output: A single helper (`resolve_ckpt_path`) applied at every `torch.load(
os.path.join(args.ckpt_path, get_ckpt_name()), ...)` call site in `main.py`.
All existing eval modes continue to work with directory-form `--ckpt_path`.
</objective>

```python
def resolve_ckpt_path(ckpt_path: str) -> str:
    """
    Resolve --ckpt_path to an absolute file path.

    - If ckpt_path ends with '.pkl' AND is an existing file, return it verbatim
      (D-01: enables loading non-canonical checkpoints like 2016.10a_AWN_at.pkl
      without editing get_ckpt_name()).
    - Otherwise treat ckpt_path as a directory and join with get_ckpt_name()
      (existing behavior; --ckpt_path ./checkpoint -> ./checkpoint/2016.10a_AWN.pkl).
    """
    if ckpt_path.endswith('.pkl') and os.path.isfile(ckpt_path):
        return ckpt_path
    return os.path.join(ckpt_path, get_ckpt_name())
```

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI → filesystem | --ckpt_path value comes from untrusted argv and is passed to torch.load (a pickle-based deserializer that executes arbitrary code on load without weights_only=True) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01-01 | Tampering | main.py resolve_ckpt_path → torch.load | accept | This is a research tool run by the author on trusted machines; torch.load call sites in main.py already use `weights_only=True` for detector loads, but classifier loads in eval modes currently do not. Scope-limited: the shim does NOT change the weights_only posture of any torch.load call — it only changes the resolved path. Threat posture identical to pre-shim. Upgrading to weights_only=True across all classifier loads is a future concern (existing shipped v1.0 checkpoints are trusted; AT checkpoint was just trained locally by the same user). |
| T-05-01-02 | Information Disclosure | filesystem path handling | accept | --ckpt_path is a user-supplied path. resolve_ckpt_path() only calls os.path.isfile and os.path.join; it does not follow symlinks specially, expand env vars, or fetch from network. No new path-traversal surface vs. current os.path.join behavior. |
| T-05-01-03 | Denial of Service | Malformed ckpt_path string | accept | An empty-string or non-existent path falls through the isfile check and becomes `os.path.join('', '2016.10a_AWN.pkl')` = `'2016.10a_AWN.pkl'`, which torch.load then raises FileNotFoundError on. Same failure mode as pre-shim. Acceptable. |
